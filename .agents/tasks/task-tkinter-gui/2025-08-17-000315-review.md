# Tkinter GUI audit fixes (v2 re-review)

This is a second-pass review after all 7 issues from the v1 review were addressed in commit a12bf06. The fixes add a `_state_lock` for thread-safe engine transitions, a `_process_message_queue` consumer that reconciles button states, input validation via `_is_valid_mac` and `_is_valid_ip`, cancellable refresh scheduling with `_schedule_refresh`/`after_cancel`, a working `_clear_database` implementation, and a `_trim_log_widget` ring buffer.

Watch for: `_on_close` calls async stop methods then immediately destroys the window, so stop-threads may attempt Tk widget updates on a destroyed root (likely); `_clear_database` interpolates table names into SQL with bracket-escaping that is fragile if a table name contains `]` (possible).

**Verdict**: APPROVED

## High-level view

The seven v1 issues are resolved. The `_state_lock` wraps all check-then-set and stop-then-nullify sequences consistently across all four engine lifecycle pairs. The message queue consumer polls at 200ms and maps message types to button/label state, closing the UI-desync gap. Input validation rejects malformed BSSIDs and IPs before they reach engine constructors. The refresh timer is now properly cancelled and rescheduled when the interval changes.

Two new minor concerns emerge. The shutdown sequence fires off stop-threads then synchronously destroys the Tk root, creating a window where those threads' `finally` blocks may post messages that the consumer tries to render on destroyed widgets. The `_clear_database` SQL uses bracket quoting that SQLite tolerates but that doesn't handle a `]` in table names — academic given the schema is self-controlled, but worth noting.

## Shutdown sequence and Tk teardown

`_on_close` dispatches up to four stop operations, each spawning a daemon thread that calls `.stop()` on engines and posts a `*_stopped` message in `finally`. Immediately after dispatching, the method calls `self.root.destroy()`. The daemon threads continue executing — they'll call `engine.stop()`, set state flags, and invoke `self.message_queue.put(...)`. The `put` itself is safe (queue outlives Tk), but if `_process_message_queue`'s scheduled `after` callback fires between the stop-thread posting and `destroy()` completing, it will call `self.recon_start_btn.configure(state="normal")` on a widget whose underlying Tcl interpreter is being torn down.

On CPython/Linux this typically manifests as a swallowed `TclError`. On Windows with certain Tk versions it can produce a crash dialog. The simplest fix:

```python
def _on_close(self):
    self._shutting_down = True
    # ... stop engines ...
    self.root.after(500, self.root.destroy)  # give stop-threads time
```

And in `_process_message_queue`:

```python
if getattr(self, '_shutting_down', False):
    return  # don't reschedule or touch widgets
```

## SQL table-name quoting in _clear_database

```python
cursor.execute(f"DELETE FROM [{table}]")
```

Square-bracket quoting is a SQL Server/MS Access convention that SQLite tolerates. SQLite's native identifier quoting uses double-quotes (`"table"`) or backticks. A table name containing a literal `]` would break the bracket quoting. Since the names are read from `sqlite_master` for a schema this application creates, the risk is academic — but switching to `f'DELETE FROM "{table.replace(chr(34), chr(34)+chr(34))}"'` would be more correct.
