# VLAN scanning and network segmentation mapping (v2)

All seven issues from the v1 review have been addressed: SQLite cursor operations are now wrapped in `self._lock`, ARP sweeps start a background sniff thread before sending requests, the NTLM SMB server binds to the interface-specific IP, the orchestrator uses the new `wait_for_completion()` public API, `_packets_processed` is incremented under the lock, `_parse_cidr` is extracted to shared `net_utils.py`, and the hccapx message pair is derived from captured messages. Additional fixes include stale iptables cleanup on HTTPS interceptor start and `0o600` permissions on wpa_supplicant configs.

Watch for: Inter-VLAN routing probes are sent untagged from the attack machine's native VLAN rather than tagged from each source VLAN, so the detection measures whether the attack machine can reach other segments — not whether VLANs can reach each other (confirmed). The payment segment classifier triggers on ≥2 ports from a set that includes 443 and 8443, causing standard HTTPS servers to be classified as payment infrastructure and inflating ACL gap severity (confirmed). Per-segment `acl_gaps` persisted to the database is always an empty list because detected gaps are only stored in the global `_acl_gaps` collection and never back-propagated to the segment dict (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The VLAN scanner implements passive discovery (802.1Q sniffing, CDP/LLDP parsing) and active attacks (DTP spoofing, double-tag Q-in-Q hopping) with correct protocol-level framing.

The network segmentation mapper builds on top of VLAN discovery, adding per-segment ARP+port-scan host enumeration, a classification heuristic (management/payment/guest/server/workstation), inter-VLAN routing detection, and ACL gap analysis. The routing detection has a conceptual gap: it sends raw IP/ICMP from the attack machine's own network stack rather than tagging probes with the source VLAN, so it only proves that the attack machine has L3 reach — not that the two VLANs can communicate. The ACL gap detector only tests from `guest` or `unknown` source types, missing `workstation` → `payment` and `server` → `management` paths that are equally critical in POS environments.

The `parse_cidr` utility ignores the prefix length and always generates a /24 (254 hosts) regardless of whether the input is a /16 or /28. For segments where the VLAN scanner guesses the range from ARP traffic, a /28 will get 254 probes aimed at non-existent addresses.

The database persistence layer for segments and routes uses plain INSERTs without upsert semantics. If `_persist_results` is called more than once (it is: both `map_all()` and `stop()` call it), duplicate rows accumulate for the same segment/route.

<details>
<summary>Issues (5)</summary>

1. **Untagged inter-VLAN routing probes** — `_detect_inter_vlan_routing` sends plain IP/ICMP probes from the attack machine's stack rather than VLAN-tagged frames from each source VLAN. This detects the attack machine's own reachability, not true inter-VLAN routing. Tag probes with the source VLAN or document the limitation clearly.
2. **Payment classifier false positives** — `PAYMENT_PORTS` includes 443 and 8443. Any HTTPS server with both ports triggers `segment_type = "payment"`, which cascades into high-severity ACL gap findings. Remove generic HTTPS ports from the payment set or require a POS-specific port (4100, 9100, 20000) to be present.
3. **Per-segment acl_gaps always empty in DB** — Detected ACL gaps are appended to `self._acl_gaps` but never written back to the segment's `"acl_gaps"` list. The database gets `acl_gaps="[]"` for every segment. Either back-propagate gaps to the relevant segment dict before `_persist_results`, or remove the per-segment field and rely solely on the global list.
4. **Duplicate segment/route rows on repeated persist** — `log_segment` and `log_vlan_route` use plain INSERT without ON CONFLICT handling. Since `_persist_results` is called from both `map_all()` and `stop()`, each route/segment gets two rows. Add `ON CONFLICT` upsert or guard against double-persist.
5. **`parse_cidr` ignores prefix length** — Any CIDR input produces exactly 254 hosts from the third octet regardless of prefix. A /28 segment will get probes for 240 non-existent hosts; a /16 will only scan the first /24. Respect the mask or at minimum clamp to the subnet boundaries.

## Inter-VLAN routing detection measures the wrong thing

The mapper sends untagged ICMP and TCP SYN probes from the attack interface:

```python
probe = IP(dst=target_ip) / ICMP()
reply = sr1(probe, iface=self.interface, timeout=self.scan_timeout, verbose=False)
```

These probes travel through the attack machine's default route. The test claims `bidirectional: 1` without probing the reverse path. Because the loop iterates `(src_vlan, dst_vlan)` pairs but sends from the attack machine regardless of `src_vlan`, every "route detected" finding describes the same reachability: attack machine → target host. Two VLANs that are mutually isolated but both reachable from the attack machine will both report routes to each other.

For accurate inter-VLAN routing detection, probes should either be sent with Dot1Q tags matching the source VLAN (requiring a trunk port) or the test should be run after pivoting into each VLAN. Alternatively, the findings should be labeled as "reachable from attack position" rather than "inter-VLAN route."

## Payment segment classification overlap

`PAYMENT_PORTS = {443, 8443, 9100, 4100, 20000}` — ports 443 and 8443 appear on virtually any segment running HTTPS services. The classification triggers at ≥2 matches:

```python
payment_overlap = all_ports & PAYMENT_PORTS
if len(payment_overlap) >= 2:
    return "payment"
```

A corporate web server running HTTPS on 443 and a management panel on 8443 will be classified as "payment." This inflates the ACL gap detector's output because traffic to "payment" segments gets `severity: "high"`. A segment with only 443 + 8443 (no management ports) becomes "payment" instead of the more likely "server."

The fix is either requiring at least one POS-specific port (4100, 9100, 20000) alongside the generic HTTPS ports, or requiring ≥3 matches from the payment set.

## ACL gap data path disconnect

In `scan_segment`, each segment record is created with `"acl_gaps": []`. Later, `_detect_acl_gaps` appends findings to `self._acl_gaps` (the global list) but never updates `self._segments[dst_vlan]["acl_gaps"]`. When `_persist_results` runs, it serializes `seg.get("acl_gaps", [])` — always the original empty list — into the database. Anything downstream querying `network_segments.acl_gaps` expecting populated data will find nothing.

## Database duplicate rows

`_persist_results` is called unconditionally by both `map_all()` (at the end of mapping) and `stop()` (in the orchestrator's shutdown sequence). Neither `log_segment` nor `log_vlan_route` uses UPSERT:

```python
def log_segment(self, vlan_id, ...):
    self.cursor.execute('''
        INSERT INTO network_segments (vlan_id, ...) VALUES (?, ...)
    ''', ...)
```

Since `network_segments` uses an auto-increment `id` primary key and `vlan_id` has no UNIQUE constraint, each call inserts a new row. After a normal run, every segment and route will have two identical rows — once from `map_all()` and once from `stop()`.
