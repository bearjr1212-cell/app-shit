# Handshake capture, credential intelligence, and VLAN scanning expansion

POSFramework gains four major capability areas: PMKID clientless capture with hashcat export and multi-AP parallel sniffing; a full credential intelligence pipeline (HTTPS interception, session hijacking, NTLM/Kerberos/LDAP capture, cloud credential detection, certificate auth detection); credential operations (spraying, enrichment, auto-pivot, browser extraction, hashcat integration, correlation engine, client profiling); and VLAN discovery with network segmentation mapping. The implementation spans ~18,000 new lines across 25+ modules, all wired into the orchestrator's phased attack flow and persisted through new database tables.

**Watch for:** SQLite cursor operations lack per-operation locking despite multi-threaded writes from VLAN scanner, credential modules, and the orchestrator simultaneously (confirmed). ARP sweep in both VLANScanner and NetworkMapper starts the response sniff *after* all requests are sent, missing early responses (confirmed). The NTLM capture SMB server binds `0.0.0.0:445` with no interface restriction (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The database layer gained new tables (vlans, network_segments, vlan_topology, enriched_credentials, client_profiles, credential_correlations, printers, print_jobs, printer_credentials) with proper upsert semantics, but the concurrency model is incomplete: only `_maybe_commit` acquired the lock, while every `cursor.execute` call across dozens of concurrent threads remains unprotected — WAL mode reduces but doesn't eliminate corruption risk under heavy concurrent writes.

The VLAN scanner implements five discovery methods (802.1Q sniffing, CDP parsing, LLDP parsing, DTP spoofing, double-tag hopping) with real protocol-level parsing. The network mapper builds on top, adding per-VLAN ARP sweeps, TCP port scans, segment classification (management/payment/guest/server/workstation), inter-VLAN routing detection, and ACL gap analysis. Both modules have a design flaw in ARP sweep timing: requests are sent sequentially then a response sniff starts afterward — early ARP replies arriving during the send phase are lost.

The handshake system adds deduplication, beacon caching for PCAP prepend, .hccapx and mode-22000 export, FT (802.11r) detection, and an autonomous `HandshakeSniffer` class. The PMKID extraction correctly parses EAPOL Message 1 Key Data for the vendor-specific KDE (OUI 00:0f:ac type 04). The .hccapx export hardcodes message pair to `0` regardless of which EAPOL messages were actually captured.

Credential capture modules follow a consistent architecture: scapy sniff loop → protocol parser → structured result storage. The HTTPS interceptor properly tears down iptables on `stop()`, but a crash leaves the PREROUTING redirect rule orphaned. The NTLM SMB server binds all interfaces without restriction.

The orchestrator integrates all modules via 12 new `enable_*` constructor parameters. It accesses `VLANScanner._sniff_thread` directly in `_run_vlan_scan`, breaking encapsulation.

<details>
<summary>Issues (7)</summary>

1. **SQLite cursor concurrency** — `cursor.execute()` calls are not protected by any lock, only `_maybe_commit` is. Add a connection-level lock around all execute+commit sequences, or switch to one-connection-per-thread with a shared WAL database.
2. **ARP sweep misses early responses** — Both `VLANScanner.arp_scan_vlan` and `NetworkMapper._arp_sweep` send all ARP requests first, then start a 5-second sniff. Responses arriving during the send phase (~1.3s for a /24) are lost. Overlap send and sniff using a background thread or scapy's `srp()`.
3. **NTLM SMB server binds 0.0.0.0:445** — No interface binding, so the fake SMB server accepts connections from any interface on a multi-homed machine. Bind to the specific interface IP or document the exposure.
4. **Orchestrator accesses VLANScanner private `_sniff_thread`** — `_run_vlan_scan` does `self.vlan_scanner._sniff_thread.join(timeout=35)`. Expose a public `wait()` or `join()` method instead.
5. **`_packets_processed` counter not under lock** — Incremented in `_packet_handler` (sniff thread) and read from `get_stats()` (main thread) without locking. Safe under CPython GIL today, but invites bugs. Use the existing `_lock`.
6. **`_parse_cidr` duplicated** — Identical implementation in `vlan_scanner.py` and `network_mapper.py`. Extract to a shared utility.
7. **No test coverage** — Zero tests for 25+ new modules. Critical protocol parsers (NTLM Type 3, Kerberos ASN.1, EAPOL message identification, CDP/LLDP TLV parsing) need at least unit tests.

## SQLite concurrency model gap

The database uses `check_same_thread=False` and WAL mode, but the protection is asymmetric. The new `_commit_lock` only guards `_maybe_commit`:

```python
def _maybe_commit(self):
    now = time.monotonic()
    with self._commit_lock:
        if now - self._last_commit >= COMMIT_INTERVAL:
            self.conn.commit()
            self._last_commit = now
```

Every other method (`log_vlan`, `log_segment`, `store_enriched_credential`, `log_printer`, etc.) calls `self.cursor.execute(...)` then `self._maybe_commit()` without any lock around the execute. With the orchestrator running VLAN scanner, network mapper, credential harvester, printer recon, and client profiler all writing concurrently, interleaved cursor operations on a shared cursor object can corrupt results. SQLite's WAL mode makes concurrent *connections* safe, but a single shared connection + cursor called from multiple threads needs serialization or one-cursor-per-call.

## ARP sweep timing gap loses early responses

In `VLANScanner.arp_scan_vlan`:

```python
for host_ip in hosts:
    sendp(frame, iface=self.interface, verbose=False)
    time.sleep(0.01)

# Collect responses via brief sniff
responses = sniff(iface=self.interface, filter="arp", timeout=5, store=1)
```

For 254 hosts at 10ms each, sending takes ~2.5 seconds. ARP responses from early hosts arrive within milliseconds and are not captured because the sniff hasn't started yet. The same pattern appears in `NetworkMapper._arp_sweep` (5ms delay, ~1.3s total send time). Fix by sniffing concurrently with sending (background sniff thread started before the send loop) or using scapy's `srp()`.

## Network segment classification false positives

The payment segment classifier triggers on ≥2 ports from {443, 8443, 9100, 4100, 20000}. Since 443 and 8443 are common on any HTTPS server, a standard web server with an HTTPS management panel gets classified as "payment." This cascades into the ACL gap detector, which assigns higher severity to traffic reaching "payment" segments.

The ACL gap detector only tests from `guest` → `management`/`payment`. It doesn't test `workstation` → `payment` or `server` → `management`, which are equally common segmentation violations in POS environments.

## NTLM SMB server exposure

```python
self._smb_server.bind(("0.0.0.0", 445))
```

The fake SMB server is reachable from any network interface, not just the target network. On a multi-homed attack machine this exposes the capture server to unintended networks and requires root privileges (port < 1024).

## Handshake .hccapx message pair hardcoded

The message pair byte is hardcoded to `0` (M1+M2 pair):

```python
hccapx += struct.pack("B", 0)
```

If the capture contains M2+M3 or M3+M4, hashcat needs the correct message pair value (`2` or `5` respectively) to compute the MIC correctly. Derive the value from the actual messages in `data["messages"]`.

## HTTPS interceptor stale iptables on crash

If the process is killed (SIGKILL) or crashes before `stop()` runs, the NAT PREROUTING rule persists and all port-443 traffic on the interface continues to redirect to a dead port. Add a startup check that removes any matching stale rule before adding a new one.

## Auto-pivot writes credentials world-readable

```python
with open(config_path, "w") as f:
    f.write(f'    psk="{password}"\n')
```

The wpa_supplicant config in `/tmp/` is created with default permissions (typically 0644). On a shared machine, other users can read the cracked PSK. Set `os.chmod(config_path, 0o600)` after writing.

## Orchestrator encapsulation breach

```python
def _run_vlan_scan(self):
    self.vlan_scanner.start()
    if self.vlan_scanner._sniff_thread:
        self.vlan_scanner._sniff_thread.join(timeout=35)
    self.vlan_scanner.stop()
```

The scanner's `stop()` already joins its thread internally with a 5s timeout, making the explicit join here redundant but with a longer timeout. Add a public `wait_for_completion(timeout)` method to `VLANScanner` instead of reaching into private state.
