# VLAN scanning and network segmentation mapping (v3)

All five issues from the v2 review have been addressed. Inter-VLAN routing probes now carry `Ether()/Dot1Q(vlan=src_vlan)/IP()/ICMP()` with an explicit docstring noting trunk port requirements and labeling limitations of access-port positions. The payment classifier requires at least one POS-specific port (4100, 9100, or 20000) — generic HTTPS alone no longer triggers. ACL gaps are back-propagated to per-segment dicts via `_propagate_acl_gaps()` before persistence. The `_persisted` flag prevents duplicate DB rows from the `map_all()`/`stop()` double-call path. `parse_cidr` now respects prefix length with correct handling of /32 (1 host), /31 (2 hosts, RFC 3021), standard subnets (network/broadcast excluded), and large-prefix clamping to 1024 hosts.

Watch for: VLAN-tagged probes use `Ether(dst="ff:ff:ff:ff:ff:ff")` as the destination MAC for unicast IP/ICMP, which may cause switches to flood the frame across the VLAN or drop it depending on configuration — using the default gateway's MAC would be more reliable for routed probe delivery (likely). The route direction was corrected from `bidirectional: 1` to `bidirectional: 0`, but the `(i, i+1)` iteration only tests each pair in one direction; asymmetric routing won't surface without a reverse pass (confirmed, pre-existing by design).

**Verdict**: APPROVED

## High-level view

The inter-VLAN routing fix correctly tags probes at Layer 2 with the source VLAN ID and documents access-port limitations. The remaining gap is the broadcast destination MAC on an otherwise-unicast IP probe — switches with strict unicast forwarding or storm-control ACLs may silently drop the frame, causing false negatives in route detection.

## Broadcast destination MAC on routed probes

The fix adds `Ether(dst="ff:ff:ff:ff:ff:ff")` to both ICMP and TCP SYN probes:

```python
probe = (
    Ether(dst="ff:ff:ff:ff:ff:ff") /
    Dot1Q(vlan=src_vlan) /
    IP(dst=target_ip) /
    ICMP()
)
```

On a managed switch with the interface in trunk mode, this frame arrives on VLAN `src_vlan` with a broadcast Ethernet destination. The switch floods it to all ports in that VLAN. The default gateway will receive the frame but may or may not process the IP layer — most routers accept broadcast-MAC'd IP packets destined to their subnet, but some switch ACLs drop broadcast-framed unicast IP as a storm-control measure.

A more robust approach would ARP for the VLAN gateway's MAC during the `_arp_sweep` phase (which already tags ARP requests per-VLAN) and use that MAC as the Ether destination for subsequent routing probes. This introduces a reliability gap on hardened networks but works on the majority of real-world trunk ports.
